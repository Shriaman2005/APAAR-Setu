# Deploying the demo online (Render + MongoDB Atlas)

This puts the prototype on one public HTTPS address, with the synthetic demo data, using free tiers.
It is a **demo** deployment: all demo accounts share one password, and anyone who has the address and
that password can sign in as any role.

## How the pieces fit

| Piece | What it does | Free tier |
| --- | --- | --- |
| GitHub (private repository) | Holds the code. Render downloads it from here and redeploys after every push. | Yes |
| MongoDB Atlas (M0 cluster) | The database. Atlas clusters are replica sets, so certification transactions work. | Yes (512 MB) |
| Render (web service) | Builds the app and runs `npm start`. Express serves the API and the React app from the same address. | Yes, but it sleeps after about 15 minutes without visitors |

```
visitor's browser --HTTPS--> Render: Express (/api + React app) --> MongoDB Atlas
your laptop ------ npm run seed:live (once) -------------------> MongoDB Atlas
```

**Why not Vercel:** Vercel runs code as short-lived functions. This server validates uploads in the
background after replying, runs recovery work when it starts, keeps rate limits in memory, and accepts
5 MB uploads (Vercel functions accept 4.5 MB). Render runs it as a normal long-running server instead.

## Step 1 - Put the code on GitHub (private)

In VS Code: open **Source Control** (`Ctrl+Shift+G`) → **Publish Branch** → sign in to GitHub when
asked → choose **Publish to GitHub private repository**.

Keep it private: the repository includes the `Instruction/` PDFs. `.env`, `.env.live` and `.data/` are
ignored by Git, so your local secrets and database are never uploaded.

## Step 2 - Create the database (MongoDB Atlas)

1. Create an account at <https://www.mongodb.com/cloud/atlas/register>.
2. Create a cluster: **M0 (Free)**, provider **AWS**, region **Singapore (ap-southeast-1)**, which is
   close to Render's Singapore region (Mumbai is fine if Singapore is not offered). Untick
   "Preload sample dataset".
3. Create a database user: a username such as `apaar_app` and an **autogenerated** password. Copy the
   password now.
4. **Network Access** → **Add IP Address** → **Allow access from anywhere** (`0.0.0.0/0`) → Confirm.
   Render's free tier has no fixed IP address, so the database user's password is what protects the
   database.
5. **Connect** → **Drivers** → copy the connection string, then make two changes: replace
   `<db_password>` with the user's password, and add the database name `apaar_setu_demo` right after
   `.mongodb.net/`. It should look like this (your user, password and cluster letters differ):

   ```
   mongodb+srv://apaar_app:PASSWORD@cluster0.abcde.mongodb.net/apaar_setu_demo?retryWrites=true&w=majority&appName=Cluster0
   ```

   Autogenerated Atlas passwords contain only letters and digits. A password you typed yourself with
   characters such as `@ : / ? # %` must be URL-encoded.

## Step 3 - Load the demo data into Atlas (from your laptop)

Create a file named `.env.live` in the project folder (Git ignores it) with two lines:

```
MONGODB_URI=<the connection string from step 2>
DEMO_PASSWORD=<a new password for the live demo accounts>
```

The demo password needs 12+ characters with at least one letter and one digit, must not contain the
word "demo", and should use only letters, digits and `-`. Do not reuse your local or any real password.

Then run:

```bash
npm run seed:live
```

Check that it prints `Connected to database "apaar_setu_demo" on ...mongodb.net`. It creates the same
11 accounts and demo scenarios as the local seed, never prints the password, and refuses to run against
the database on your computer.

## Step 4 - Create the Render service

1. Sign up at <https://dashboard.render.com> with **GitHub**, and allow Render to access the repository.
2. **New** → **Blueprint** → choose the repository. Render reads [`render.yaml`](../render.yaml) and
   shows one web service, `apaar-setu`.
3. When it asks for `MONGODB_URI`, paste **exactly the same** connection string as in `.env.live`.
4. Deploy the Blueprint. The first build takes a few minutes; follow it under **Logs**. The service is
   up when the log shows `MongoDB connected to database "apaar_setu_demo"` and
   `APAAR Setu API listening`.
5. The address is shown at the top of the service page, for example `https://apaar-setu.onrender.com`
   (Render adds a few characters if that name is taken).

What `render.yaml` sets for you:

| Setting | Value | Why |
| --- | --- | --- |
| Build command | `npm --prefix server ci --omit=dev && npm --prefix client ci --include=dev && npm run build` | Installs the server, installs the client with its build tools, builds `client/dist` |
| Start command | `npm start` | Express serves the API and the built React app |
| Health check | `/api/health` | Render checks this before sending visitors to a new version |
| `NODE_ENV` | `production` | Secure cookies, production security headers, serves `client/dist` |
| `TRUST_PROXY` | `1` | Render handles HTTPS in front of the app; without this, sign-in fails |
| `SESSION_SECRET`, `CREDENTIAL_REF_SECRET` | Generated by Render | Random secrets that stay inside Render |
| `MONGODB_URI` | Asked once | The Atlas connection string |

The public address used in activation links and QR codes comes from `RENDER_EXTERNAL_URL`, which Render
provides, so `CLIENT_ORIGIN` and `PUBLIC_VERIFY_BASE_URL` are not needed.

## Step 5 - Check the live site

1. Open `https://<your-address>/api/health`. Expect `"status":"ok"` and `"transactionsSupported":true`.
2. Sign in at `https://<your-address>/login` with the demo accounts listed in the README, using the
   `DEMO_PASSWORD` from `.env.live`.
3. Give the student account a record: sign in as `operator.demo@example.test`, upload
   `fixtures/clean_batch.csv` and send it for review, then sign in as `head.demo@example.test` and
   certify it (see [`DEMO_GUIDE.md`](DEMO_GUIDE.md)).
4. Optional: open every page for every role in headless Chrome (it only reads, so the demo data is
   not changed):
   `E2E_BASE_URL=https://<your-address> node --env-file=.env.live e2e/route-sweep.mjs`

## Everyday use

- **Update the site:** commit and push (VS Code: **Sync Changes**). Render rebuilds and switches over
  automatically.
- **Before a presentation:** open the site a few minutes early. A sleeping free instance takes up to a
  minute to wake.
- **Change the live password:** edit `DEMO_PASSWORD` in `.env.live`, then
  `npm run seed:live -- --reset-passwords`.
- **Start the live data fresh:** in Atlas, open **Data Explorer / Browse Collections**, delete the
  `apaar_setu_demo` database, then run `npm run seed:live`. Everyone is signed out.
- **Take it offline:** suspend or delete the service in Render, and delete the cluster in Atlas.

## If something goes wrong

| What you see | Likely cause |
| --- | --- |
| Logs show `Server failed to start` or a server selection timeout | Atlas Network Access does not allow `0.0.0.0/0`, or the cluster address in `MONGODB_URI` is wrong |
| Logs show `bad auth` / authentication failed | Wrong database username or password in `MONGODB_URI` |
| The site loads but every sign-in says the email or password is incorrect | Render's `MONGODB_URI` names a different database than `.env.live` (compare the name after `.mongodb.net/` with the `MongoDB connected to database` log line), or the wrong password |
| Sign-in seems to work but you land back on the sign-in page | `TRUST_PROXY` is missing in Render's environment settings |
| Build fails at `npm ci` | A lock file is out of date: run `npm --prefix server install` and `npm --prefix client install` locally, commit, push |
| The first page takes about a minute | The free instance was asleep |

## Security notes for a public demo

- Every demo account, including the system administrator, uses the password in `.env.live`. Share it
  only with people who need it (for example, judges). All data is synthetic.
- `.env.live` contains the database password. Git ignores it; do not share it or paste it into chats.
- Rate limits are kept in the server's memory, so they reset whenever the free instance restarts.
- The site keeps its prototype notice: it is not an official AICTE, Ministry of Education or APAAR system.
